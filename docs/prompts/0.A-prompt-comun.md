# 0.A — Contexto común y preparación del issue

Usa este prompt para documentar una necesidad y convertirla en un issue implementable.

## Entrada

- problema u objetivo;
- repositorios afectados;
- evidencia disponible y restricciones del mantenedor.

## Instrucciones

1. Lee `AGENTS.md` completo y respeta su mapa de repositorios y contratos.
2. Comprueba el estado actual en código, companions y documentación. Separa hechos
   verificados, inferencias y propuestas.
3. Define un objetivo acotado, impacto, archivos previsiblemente afectados, invariantes,
   dependencias y criterios de aceptación observables.
4. Señala explícitamente toda superficie de seguridad, persistencia, migración,
   sincronización o protocolo. Si exige una decisión arquitectónica, crea o enlaza el ADR
   antes de proponer implementación.
5. Para cambios cross-repo, describe el par de PRs, el pin inmutable, el versionado y el
   test de contrato requeridos.
6. Incluye casos de fallo y pruebas negativas; no derives "production-ready" de pruebas de
   camino feliz.

## Salida

Entrega un issue con: problema verificado, objetivo, alcance, invariantes, aproximación
marcada como borrador cuando corresponda, tests, criterios de aceptación y dependencias.
No implementes ni presentes decisiones pendientes como hechos aprobados.
